### 결정 대기 항목 (ADR 안건)

#### ADR-001 — 플랫폼 순서

- **잠정 방향**: 1단계 모바일 최적화 반응형 웹(GitHub Pages 정적 배포) → 2단계 Android(TWA 경로) → 3단계 iOS(네이티브 계층 필요)
- **근거 지식**: GitHub Pages는 HTTPS라 브라우저 카메라 권한(`getUserMedia`) 사용 가능. 서버가 없어 사진이 기기를 떠나지 않으므로 개인정보 설계상 가장 강함(context.md §5). 반대로 iOS는 웹뷰 포장만으로는 가이드라인 4.2 반려 위험(§4).
- **쟁점**: 최종 목표가 "양쪽 마켓 출시 경험"인데 웹 1단계가 그 경험을 지연시킨다. PO는 "목표 유지, 웹은 1단계"로 답했으므로 그 전제로 작성하면 된다.

#### ADR-002~003 — 기술 스택

- **후보**: Expo/React Native, Flutter, 순수 웹 스택 / 백엔드는 Supabase 또는 없음(클라이언트 전용) / 3티어 여부
- **PO가 이 논의를 꺼낸 실제 동기 (2026-08-07 발언)**: "앱 출시는 최종장이나 지금 고려하려던건 flutter등 **개발 생산성**에 대한 부분 확정때문임" → 평가 기준의 1순위는 마켓 대응력이 아니라 **프로토타입~사용자 테스트 구간의 개발 속도**로 잡아야 한다.
- **제약 조건**: 개발자 계정 양쪽 다 없음(플레이 $25 1회, 애플 연 $99 미지출). 1단계가 웹이면 스택은 웹 우선 배포와 충돌하지 않아야 한다 — Flutter Web·React Native Web의 정적 배포 적합성이 실제 쟁점.

### 이번 세션에서 확정된 전제 (다음 세션이 다시 묻지 말 것)

- **포지셔닝은 "재미 위주"** — 정확도 경쟁 안 함. 근거: 오프라인 진단조차 재현성 없음 + 사진은 조명 편차에 더해 포토샵 편집도 가능.
- **사용자에게 촬영 도구(그레이카드) 요구하지 않음** — 재미 위주 서비스에 과한 부담.
- **당면 목표는 프로토타입 → 사용자 테스트**, 앱 출시는 최종장.
- **결과 체계는 12타입 언어를 쓸 것** — 소비자가 이미 "여름 뮤트" 수준으로 말함.
