# 003 — 1단계 백엔드 없음: 순수 클라이언트, Supabase는 조건부 재검토

- 상태: 승인 (2026-08-10)
- 결정자: PO
- 선행 결정: [001 플랫폼 순서](001-web-first-platform-order.md), [002 웹 스택](002-web-stack-vite-react-mediapipe.md)
- 관련 지식: [context.md](../context.md) §5 얼굴 이미지 개인정보

## 맥락

- 인계 문서의 기존 잠정 후보에 Supabase·클라이언트-서버-DB 3티어가 있었다.
- ADR-001로 1단계가 GitHub Pages 정적 배포로 확정되면서, 서버 계층의 필요 시점이 실질 쟁점이 됐다.
- context.md §5: 사진이 기기를 떠나지 않으면 사업자 관점에서 개인정보 "수집" 자체가 발생하지 않는다. 서버 저장 기능을 넣는 순간 이 구조가 깨지고 동의·처리방침 체계가 필요해진다.

## 결정

- **1단계는 백엔드 없음(서버·DB 0)으로 확정한다.** 분석·결과 표시 전부 클라이언트에서 수행하고, 어떤 데이터도 외부로 전송·저장하지 않는다.
- **Supabase는 폐기가 아니라 조건부 재검토 대상으로 남긴다.** 재검토 트리거: 결과 저장·공유·이력 등 서버 저장이 필요한 기능 요구가 확정될 때. 그 시점의 선행 조건: context.md §5 개인정보 구조 재검토(동의·처리방침·폐기 설계)를 먼저 통과해야 한다.

## 근거

- 당면 목표(프로토타입 → 동료 사용자 테스트)에 서버가 필요한 기능이 없다.
- "사진이 기기 밖으로 나가지 않는다"는 고지는 개인정보 설계이자 마켓 심사(애플 5.1) 대응 논리다 — 1단계에서 이 강점을 포기할 이유가 없다.
- 백엔드 부재는 개발 생산성 1순위(ADR-002 맥락)와도 정합 — 배포·운영 대상이 정적 파일뿐이다.

## 결과 (트레이드오프)

- 사용자 결과는 세션 안에서만 존재한다(새로고침하면 사라짐). 공유는 이미지 저장·스크린샷 등 클라이언트 수단으로만 가능 — 1단계 피드백 수집에는 충분하다고 판단.
- 서버 기능이 필요해지는 순간 개인정보 체계 작업이 함께 발생한다 — 이 비용을 뒤로 미룬 것이며 없앤 것이 아니다.
