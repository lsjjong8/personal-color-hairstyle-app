# 공개 구현·상용 서비스 대조와 자체 평가

**기준 시점: 2026-09-01** · 상태: 사실 수집 완료 / README 반영은 다음 회차

`context.md` §시장에 "경쟁 앱 조사 — 추후 조사 가치"로 적어 두고 미착수였던 항목을 여기서 닫는다.

이 문서는 **우리가 어디쯤 있는지**를 남긴다. 다만 우리 포지셔닝은 ADR-001과 `context.md`에서 **정확도 경쟁을 하지 않는 재미(엔터테인먼트) 위주**로 확정돼 있다(PO 확인, 2026-08-06). 따라서 "정확도가 낮으니 문제"라는 식으로 읽지 않는다 — 대신 **어느 축이 원래 어려운가**, **우리가 남들보다 실제로 나은 곳은 어디인가**를 본다.

## 1. 가장 값어치 있는 대조군 — ShowMeTheColor

[starbucksdolcelatte/ShowMeTheColor](https://github.com/starbucksdolcelatte/ShowMeTheColor) · 31★ · Jupyter Notebook · 마지막 커밋 2021-02-02 · **라이선스 명시 없음**

공개된 한국어권 퍼스널 컬러 진단 구현 중 별이 가장 많고, **드물게 자체 정확도를 공개**했다. README 설명이 아니라 소스 코드에서 확인한 사실만 적는다.

### 판정 방법 (`src/personal_color_analysis/`)

| 단계 | 내용 |
|---|---|
| 얼굴 검출 | dlib 68점 랜드마크 |
| 표본 영역 | 좌우 볼·좌우 눈썹·좌우 눈 — **6영역**을 3쌍으로 평균 |
| 대표색 추출 | 영역별 k-means(군집 4개) 후 최빈 군집 |
| 웜/쿨 축 | **Lab의 b값**(노랑–파랑 축) |
| 계절 세분 | **HSV의 S값**(채도) |
| 판정 | 기준값과의 거리에 가중치를 곱해 합산, 작은 쪽 채택 |

### 코드에 박힌 기준값

```
웜/쿨 (Lab b, [피부, 눈썹, 눈])
  웜  [11.65, 11.71, 3.65]   쿨  [4.64, 4.87, 0.19]   가중치 [30, 20, 5]

봄/가을 (HSV S, %)
  봄  [18.59, 30.30, 25.81]  가을 [27.14, 39.75, 37.50]  가중치 [10, 1, 1]
```

가중치를 보면 **피부가 웜/쿨의 55%, 봄/가을의 83%를 차지한다.** 눈썹·눈을 넣었지만 실질 기여는 작다.

### 자체 보고 정확도와 그 근거 크기

| 계절 | 정확도 |
|---|---|
| 가을 | 90% |
| 봄 | 70% |
| **여름** | **50%** |
| **겨울** | **50%** |
| 웜/쿨 축만 | 70~100% |

표본은 `res/test/` 아래 **계절당 10장, 총 40장**이다(직접 세었다). 저자 본인이 밝힌 원인: *여름과 겨울의 HSV 채도값이 명확히 구분되지 않는다.*

### 조명 보정이 없다 — 코드에서 확인

소스 전체를 `balance|gray|normali|illumin|light|exposure|white|calib`로 훑었을 때, `cvtColor`가 **얼굴 검출용 흑백 변환과 k-means용 RGB 변환에만** 쓰인다. 화이트밸런스·노출 정규화 코드가 없다. README 서술이 아니라 코드를 봤다.

## 5. 자체 평가

### 우리가 실제로 앞선 곳 (근거 있음)

1. **조명 보정.** 우리는 눈 흰자를 기준으로 색과 노출을 함께 맞춘다(ADR-006). ShowMeTheColor에는 없다 — 코드로 확인했다. 조명이 판정을 지배한다는 것은 우리가 Phase 2에서 실측으로 겪은 사실이므로, 이 차이는 문서상 차이가 아니라 결과의 차이일 가능성이 높다.
2. **채도를 명도와 묶어 본다.** 우리는 채도를 그 자체로 재지 않고 명도에 따라 기대되는 값과의 차이(잔차)로 잰다(ADR-004·007). ShowMeTheColor는 HSV 채도를 그대로 쓰고, 바로 그 축에서 여름·겨울이 갈리지 않아 50%가 나왔다. **같은 벽을 두 팀이 서로 모른 채 만났고, 우리 쪽이 한 겹 더 대비하고 있다.**
3. **웜/쿨을 색상각으로 잰다.** Lab의 b값만 쓰면 빨강–초록 축(a)을 버린다. 색상각은 둘을 함께 쓴다.
4. **입력을 못 믿을 때 그 사실을 표시한다.** 보정 건너뜀·잘린 픽셀 비율을 화면에 내보내는 구현은 조사 범위에서 우리뿐이었다.

### 우리가 뒤진 곳

1. **측정된 정확도가 없다.** ShowMeTheColor는 40장이라도 숫자를 냈다. 우리 상수는 사진 4장에서 나온 잠정값이고, 그 4장으로 검증까지 해서 **순환적이다**(ADR-007이 스스로 적어 둔 한계). 이게 지금 가장 큰 공백이다.
2. **표본 영역이 피부뿐이다.** ShowMeTheColor는 가중치가 낮긴 해도 눈썹·눈을 함께 본다. 머리카락·눈동자 색은 퍼스널 컬러 판정의 표준 입력이다.
3. **입력 품질을 사후에만 다룬다.** SKN23 팀은 촬영 **전에** 얼굴 위치·크기를 안내한다. 우리는 잘림도 찍은 뒤에 알려 준다.
4. **조명 편차를 자가응답으로 보완하지 않는다.** Clad의 설문 4문항(혈관색·햇빛 반응)은 **조명에 흔들리지 않는 정보**다. 우리가 `context.md` §2에서 "도메인의 근본 한계"로 두고 재미 포지셔닝으로 흡수한 부분을, 저쪽은 다른 종류의 입력으로 줄이고 있다.

### 종합

**방법론은 조사 범위에서 가장 정교한 축에 든다.** 조명 보정·채도의 명도 의존·입력 품질 표시 네 가지를 함께 갖춘 공개 구현은 찾지 못했다.

**그런데 그 정교함이 맞는지는 아직 아무도 모른다.** 표본이 4장이라 수치로 뒷받침된 것이 하나도 없다. 상대는 40장으로 "여름·겨울 50%"라는 **틀렸다는 사실**을 알아냈는데, 우리는 맞는지 틀린지를 알 수단이 없다. 이 상태에서 방법의 우수함을 주장하면 근거 없는 주장이 된다.

**따라서 지금 필요한 것은 방법 개선이 아니라 표본이다.** Phase 5 동료 배포가 그것이고, 우선순위는 그대로다.

## 7. 이 문서의 한계

- ShowMeTheColor의 정확도는 **저자 자체 보고**다. 우리가 재현하지 않았고, 40장의 정답 라벨이 어떻게 정해졌는지 확인하지 않았다.
- mycolor.kr·Clad의 내부 방법은 **공개돼 있지 않다.** 표의 "미상"은 없다는 뜻이 아니라 확인하지 못했다는 뜻이다.
- 조사는 GitHub 검색과 각 사이트 공개 페이지로 한정했다. 앱스토어 앱(`context.md`가 적은 "아이컬러" 등)은 보지 않았다.
